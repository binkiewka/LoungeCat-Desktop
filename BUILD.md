# Building LoungeCat

Requires Linux, a C++20 compiler, CMake 3.24 or newer, and Qt 6.4 or newer.
Run these commands from the repository root.

## Debian / Ubuntu

```sh
sudo apt-get install build-essential cmake pkg-config qt6-base-dev libqt6svg6-dev libqt6sql6-sqlite qt6-qpa-plugins libasound2-dev
cmake -S . -B build/release -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF
cmake --build build/release --parallel 2
./build/release/loungecat
```

ALSA development headers are optional in the default `-DLOUNGECAT_ALSA=AUTO` mode.
Use `ON` to require them (configuration fails if missing), or `OFF` to disable
the backend explicitly. Qt's SQLite driver, the selected display platform plugin, a
working Qt TLS backend and normal system runtime libraries must be installed.
This produces a dynamically linked executable, not an AppImage or installer.

Settings and history are stored in `~/.loungecat/`. To use a separate profile:

```sh
LOUNGECAT_DATA_DIR="$HOME/.loungecat-work" ./build/release/loungecat
```

Leave `LOUNGECAT_DB_PATH` and `LOUNGECAT_CONFIG` unset when using this isolated
profile, since those optional overrides take precedence.

## Contributor regression checks

```sh
cmake --preset debug
cmake --build --preset debug --parallel 2
ctest --preset debug
```

The repository includes normal, ASan/UBSan and TSan presets. Tests use local
fixtures and isolated temporary profiles. CI runs normal and ASan/UBSan builds;
tagged releases also require the package checks described in the
[packaging guide](docs/PACKAGING.md).

## Build the CI packages locally

Use Docker so the build baseline and dependency names match CI; this does not
install the app or development packages on the host. Start from a committed source
checkout so the generated matching-source archive identifies the exact revision.

```sh
docker build -t loungecat-builder -f packaging/Dockerfile.build .
docker run --rm --user "$(id -u):$(id -g)" -v "$PWD:/src" loungecat-builder bash packaging/build.sh
```

Artifacts are written to `dist/`. The build verifies SHA-256-pinned deployment
tools before execution; see `packaging/tools.lock.json`. To reproduce each clean
runtime check, follow [the packaging guide](docs/PACKAGING.md).


## Fedora RPM and Gentoo

Build a Fedora 44 x86_64 RPM from source in the native Fedora environment:

```sh
docker build -t loungecat-rpm-builder -f packaging/rpm/Dockerfile.build .
docker run --rm --user "$(id -u):$(id -g)" -v "$PWD:/src" loungecat-rpm-builder bash packaging/rpm/build.sh
```

RPM artifacts and its platform manifest are written to `dist-rpm/`. Gentoo's
versioned ebuild and complete overlay are generated by `bash packaging/gentoo/prepare.sh`
into `dist-gentoo/`, with the source archive cached in `build/gentoo/`.
See [the packaging guide](docs/PACKAGING.md) for install and test instructions.
All package builds require a committed, clean source checkout.
